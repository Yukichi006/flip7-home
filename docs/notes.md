## 持ち主について
- 英語が読めない。説明・メニューの文字・コメントはすべて日本語で書く
- スマホは右手で持つ。親指の届く下のほうに、よく使うものを置きたい
- 見た目は「黒い布地に白い糸のステッチ」。部品を足すときも、この雰囲気（ワッペン・縫い目・まち針・巾着・ファスナーなど）にそろえる
- 通知の印などのアクセントの色は、オレンジ（`Thread.ALERT`）だけにしている
- 直してほしいことは、スクリーンショットで送ってくる。実機を見てから細かく直す、の繰り返しで進めている

## ホーム画面の作り（0.28.0 から）
- 「片手の画面」「マス目の画面」の区別はない。どのページも同じマス目（最初は 5 列。マスの形はパッドに合わせ、行の数は画面の高さで決まる）
- 部品はどれもブロックとして、好きな場所に好きな大きさで置く。めくれるアプリのパネルも部品（`BOOK`、2×2 から）
- 持ち主の今の使い方：1 ページ目に主な情報（日付・電池・アナログ時計・再生中の曲・天気・フェーダー・アプリ一覧のウィジェット・Suica・めくれるパネル）、2 ページ目はカレンダーのウィジェットを画面いっぱいに
- 下段のポケットの口はファスナー。開き具合がアプリ一覧の開き具合とつながっている（ポケットの上の縁の線から下からせり上がる）
- 「…」の設定は、まとまりごとの一覧（0.32.0）。編集の帯は上下にずらせる
- 縫い付けメモ（0.33.0 → 0.35.0 で作り直し）：正方形の布の付箋。つまんで引くと角からめくれ、引ききって離すとはがれて落ちる＝完了
  - 0.39.0（持ち主の希望）：ジャンルと納期を付けられる。色はジャンルで決まる（なし＝生成り・仕事＝淡い水色・家のこと＝淡い黄・買い物＝淡い桃・趣味＝淡い若草。`PinGenre.ALL`、番号で保存するので足すときは後ろに）。
    納期の近い順に上から並ぶ（納期なしは後ろ。同じ納期は新しく書いたものが前）。長押しは「いちばん前へ」をやめて「書き直す欄」に変えた（並びは納期で決まるため）。
    前の作りの付箋は、ジャンルなし（生成り）・納期なしで読む（前は文字から色を決めていたので、色が生成りに変わる）。
    書く欄は、キーボードが下半分をふさぐので、ジャンル・納期を文字の欄より上に置いた
  - 0.40.0（持ち主の希望）：納期の札が 5 つ並んで文字が見切れていた（「な…」「今…」）ので、「今日」「今週」「今月」「なし」の 4 段を横に滑らせるつまみ（`DueSlider`）に変えた。
    「明日」と「日付を選ぶ」はやめた（持ち主が 4 択でいいと言った）。今週＝その週の日曜（日曜なら今日と同じ日）、今月＝その月の末日。見出しに「：11/30（月）まで」と決まった日を添える。
    保存は今までどおり日付なので、前の作りの付箋もそのまま。書き直すときは、同じ日の段か、収まるいちばん近い段につまみを置き、つまみを動かさなければ元の日付のまま（`PinTask.stopOf`）
- 見た目は空いているのに置けないことがあった（見えない部品がマスに残っていた）。0.35.2 で、置く前に片付け、置けなければ知らせるようにした

## ほかのアプリのウィジェット（何度も直したところ）
- 新しい作り（`android:id/background` の印があるもの。アラームなど）：余白をとらず、マスいっぱいの大きさで渡す。縮めない。小さく渡すと 2×2 で中身が出なくなる
- 古い作り（印がないもの。Suica など）：余白をとる。中身がマスより大きければ、本来の大きさで描いてから縮めて収める
- マスいっぱいに広がる作り（カレンダーなど）：中身を制限なしで測らない（測ると縮んでしまう）
- 角は Android の決まった丸み（`system_app_widget_background_radius`）で丸める。印がなければ、背景のある部品から土台を推し量る
- ウィジェットの中の一覧が指を取っても、左右のスワイプはページの切り替えに使う
- ウィジェットの中身そのものを刺繍風に描き直すことはできない（アプリが描いた絵が届くだけ）。代わりに、縁にステッチを縫える（大きさはそのまま）

## 電池の部品（0.36.0〜0.38.1 で作り直し）
持ち主の希望：「Fit3 とスマートリングの残量が出ないとニーズがない」。0.38.1 で、本体・Buds・Fit3・リングの 4 台がそろって出た（実機で確認）。

### 今の作り（どの機器を、どう読むか）
| 機器 | 読み方 | ファイル |
|---|---|---|
| 本体 | Android の電池の知らせ | `BatteryPatch` |
| Galaxy Buds | Android に残量を報告するので、そのまま読む | `BatteryPatch` |
| Galaxy Fit3 | Galaxy 標準の「バッテリー」ウィジェットを**画面に出さずに動かし**、「%」の文字を読む（新しい権限なし） | `WidgetBattery` |
| リング（evofit C8E7） | つないだまま、独自のサービスで「機器の情報」を問い合わせて答えを読む | `BleBattery` `RingPacket` |
- 名前は持ち主が付けたもの（「Yuki の…」など）で長く見切れるので、名前の代わりに**種類のアイコン**（本体・イヤホン・時計・リング）を縫い、この順に並べる（0.38.1）。
  種類は `WidgetBattery.kindOf`：リングとしてつないだ機器 → リング／名前の言葉（Buds・Fit・Watch など）／Bluetooth の機器の分類（音声 → イヤホン、身に着けるもの → 時計）。「バッテリー」から読んで種類が分からなければ時計。分からない機器は名前を出す
- 出すのは 4 台まで。少し前に読んだ残量（30 分より前）には「2時間前」などと添える
- 電池の部品の設定（編集モードでタップ）：「Galaxy の「バッテリー」から読む／やめる」「読み取りの様子を見る（診断）」「Bluetooth 機器を調べる（リングなど）」「調べた記録を見る」

### Fit3（Galaxy の「バッテリー」ウィジェット）
- Fit3 は残量を Galaxy Wearable にしか送らず、標準の電池サービスを直接読んでも出ない（FlipCover で試した）
- 「バッテリー」ウィジェットには、本体・Fit3・Buds の順に、名前なし・絵と「%」だけで出る。
  名前がないので、いちばん上を本体、Android から読めている機器と同じ残量の行はその機器とみなし、残りに「つながっているのに残量の読めない機器」の名前を当てる（`WidgetBattery.merge`）
- Samsung の更新でウィジェットの作りが変わると読めなくなる。そのときは「読み取りの様子を見る（診断）」の「ウィジェットの中身」を送ってもらう

### リング（evofit C8E7、Galaxy Ring ではない）
- 中身は Jieli（zhuhai_jieli）のチップ、ファームウェア 2.18。電池サービス（180f / 2a19）はあるが、読むと空
- 独自のサービス `be940000-7333-be46-b7ae-689e71722bd5`（be940001 書＋示＝問い合わせと答え、be940002 書、be940003 示＝実時間のデータ）。
  値の包み：`[種類][番号][全体の長さ 2 バイト LE][中身][CRC-16/CCITT-FALSE 2 バイト LE]`（`RingPacket`）
- **残量は「機器の情報」の包み（種類 02・番号 00）**：中身 `[機器の番号 2][版 2（小・大）][電池の状態 1][残量 % 1]…`。
  例 `02 00 1e 00 a3 00 12 02 00 3c …` ＝ 機器 163・版 2.18・残量 0x3c = 60%（版がアプリの表示と一致したので並びは確か）
- FlipHome からの問い合わせ（0.38.0、**持ち主の了承済み**）：`02 00 08 00 47 43 6f ec`（中身「GC」、YC 系のリングでよく使われる形）を先に送り、答えがなければ `02 00 06 00 0e c3`。
  答えが返った形を覚える（設定ファイル `ble_battery` の `query_form`）。ホーム画面が見えているときは前に読んでから 10 分、見えていないときは 1 時間ごと。専用アプリが問い合わせた答えも読む
- **リングへ送ってよいのは、この 2 通りの問い合わせだけ**。種類 02 は読み取りの質問。設定を変える・リセットする種類の包みは作らない（作る関数も用意していない）
- 専用アプリは 1〜2 分おきに `02 26`・`02 32` を問い合わせ、リングは中身 fc（対応していない）と答えている。知らない質問には fc を返すだけ
- **心拍（2a37）と歩数（fea1：歩数・距離・消費 kcal）も、新しい権限なしで 1 秒ごとに読める**（「歩数の糸巻き」の案に使える）。
  実時間の包み 種類 06・番号 00 にも歩数・距離・消費が入っている
- 診断（`BleInspector` と `Inspection`）：サービスの一覧・読める値・届いた通知を 3 分記録（同じ値のくり返しは省く）。機器へは書き込まない（通知の設定だけ。切ってあったものは終わるときに戻す）。
  専用アプリへ切り替えても続け、戻ってから「調べた記録を見る」で見る（0.36.1 では、切り替えでパネルが閉じて診断も止まっていた → 0.36.2 で直した）

## リリースと確かめ方
- `main` に push すると、GitHub Actions が正式版をビルドして Releases に出す。持ち主は Obtainium で更新する
- README だけを直して push すると、同じバージョンで出そうとしてリリースの手順が止まる（決まりどおりの止まり方で、APK には影響しない）
- 0.36.0〜0.38.1 の進め方：作業用のブランチに push → GitHub Actions の「Build APK」をそのブランチで手動実行（workflow_dispatch。テストとビルドだけで、リリースはしない）→
  持ち主が「リリースして」と言ったら main へ送る（fast-forward）。持ち主はリリースのたびに「リリースして」と返事をくれる
- テストはリポジトリの `app/src/test` にある（配置の計算・めくれるパネルの中に置く・縫い付けメモ・なぞる刺繍の外枠）。GitHub Actions が配る前に毎回動かし、落ちたらリリースも止まる（CLAUDE.md の「テスト」）
- この開発環境からは Android SDK と Google の Maven に届かないので、手元では kotlin-jvm で android-all.jar に対してコンパイルして確かめ、Robolectric でスクリーンショットを撮って見た目を確かめていた（その道具はセッションの一時フォルダにあったので、使うときは作り直す）
  - 0.36.0 のとき：Maven Central の大きいファイルは gcp.mirrors.maven.org へ飛ばされて止まる。`maven-central.storage-download.googleapis.com/maven2/` からなら取れた。
    Robolectric は androidx.test（Google の Maven にしかない）が要るので、手元では動かせなかった。画面の部品を使わないテスト（`WidgetMergeTest`・`RingPacketTest`）だけ手元で動かした
  - 手元の道具の作り方：kotlin-compiler-embeddable 2.0.21 と依存（stdlib・script-runtime・reflect 1.6.10・daemon・trove4j・coroutines 1.6.4・annotations 13.0）と
    android-all（15-robolectric-12650502）を repo1.maven.org から取り、`K2JVMCompiler -no-stdlib -jvm-target 17 -classpath android-all.jar:kotlin-stdlib.jar` でコンパイル。
    テストは一時フォルダに Gradle の kotlin("jvm") の小さな作りを置き、repo1.maven.org を使い（repo.maven.apache.org は 429 で断られることがある）、android-all を compileOnly・testCompileOnly・testRuntimeOnly に入れて動かした
- 本物のウィジェット・Galaxy の動き・指の感覚は、テストでは確かめられない。実機で見てもらう
